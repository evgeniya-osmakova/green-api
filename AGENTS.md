# Project

React + TypeScript + Vite приложение для отправки/получения текстовых Telegram-сообщений через GREEN-API.

Документация: https://green-api.com/telegram/docs/

## Requirements

• Пользователь переходит на сайт чата и вводит свои учетные данные из системы
GREEN-API (idInstance, apiTokenInstance)
• Пользователь вводит номер телефона получателя и создает новый чат
• Пользователь пишет текстовое сообщение и отправляет его получателю в Telegram
• Получатель отвечает на сообщение в мессенджере Telegram
• Пользователь видит ответ получателя в чате

Получение сообщений реализовать через GREEN-API HTTP API:

`ReceiveNotification` + `DeleteNotification`.

Простой современный интерфейс web-мессенджера в духе Telegram Web.

После подключения:

- sidebar слева с текущим чатом;
- активный чат справа;
- header чата;
- сообщения-bubbles;
- входящие слева, исходящие справа;
- composer снизу.

До подключения — минимальная форма credentials.

Если чат не создан — форма создания чата.

## Architecture

GREEN-API вынести в отдельную папку api. Использовать fetch c таким возвращаемым результатом: type Data<T> = { status: 'loading' }
   | { status: 'error'; error: ApiError }
   | { status: 'success'; data: T } .Не делать API-запросы из UI-компонентов.

Компонент и его стили лежат рядом:

Component/
  Component.tsx
  Component.module.css

Один `.module.css` = один `.tsx`.

Использовать BEM-классы внутри CSS Modules.

Приватные дочерние компоненты хранить внутри родителя:

Parent/
  Parent.tsx
  Parent.module.css
  components/
    Child/
      Child.tsx
      Child.module.css

Общие компоненты выносить выше только при реальном переиспользовании.

Не переусложнять архитектуру.

## GREEN-API

Перед реализацией API сверяться с актуальной официальной документацией.

Нужно:
- SendMessage для отправки;
- HTTP API / ReceiveNotification + DeleteNotification для получения;
- только текстовые сообщения;
- корректная фильтрация notification;
- защита от duplicate messages;
- корректный lifecycle/cancellation polling.

## Credentials

В production credentials вводятся пользователем через UI и хранятся только в runtime state.

Для моей локальной разработки можно временно использовать `.env` для prefill формы:
- `.env` обязательно в `.gitignore`;
- `.env.example` не нужен;
- реальные credentials не коммитить/логировать;
- перед финальной сдачей env-интеграцию удалить;
- приложение должно работать без `.env`.
